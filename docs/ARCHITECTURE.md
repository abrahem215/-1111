# هندسة وتصميم مشروع AirType AI

## 1. نظرة عامة على النظام (System Overview)

يهدف مشروع **AirType AI (لوحة الكتابة في الهواء)** إلى تقديم تجربة إدخال نصوص طبيعية بالكامل دون لمس لوحة المفاتيح المادية، بالاعتماد على كاميرا الجهاز العادية (Webcam على الكمبيوتر، والكاميرا الأمامية على أندرويد) وخوارزميات الرؤية الحاسوبية ومعالجة الإشارات في الوقت الحقيقي.

---

## 2. تدفق البيانات (Data Processing Pipeline)

```
[Camera Feed (RGB)]
         │
         ▼
[Mirroring & Preprocessing] (مرآة الإطار ليكون التوجيه طبيعياً)
         │
         ▼
[MediaPipe Hand Landmarker] (اكتشاف 21 نقطة يد ثلاثية الأبعاد)
         │
    ┌────┴──────────────────────────┐
    ▼                               ▼
[طرف السبابة Landmark 8]   [طرف الإبهام Landmark 4 + نقاط الكف]
    │                               │
    ▼                               ▼
[فلتر التنعيم EMA / Anti-Jitter]  [حساب مسافة الضم + الكف المفتوح]
    │                               │
    └────┬──────────────────────────┘
         │
         ▼
[Gesture State Machine] (آلة حالات الإيماءات: فحص زمن الثبات ومنع التكرار)
         │
         ▼
[Layout Engine & Hit-Testing] (تحديد الحرف النشط حسب إحداثيات السبابة)
         │
         ▼
[System Keyboard Adapter]
    ├── Windows: SendInput API (KEYEVENTF_UNICODE)
    └── Android: InputMethodService (InputConnection.commitText)
```

## 3. آلة حالات الإيماءات ومنع التكرار (Gesture State Machine)

تتألف آلة الحالات من 6 حالات رئيسية تضمن عدم تكرار الحروف عند استمرار المستخدم في ضم أصابعه:

1. **NO_HAND (لا توجد يد)**:
   - الكاميرا لا تكتشف يداً. يتم تصفير حالات الفلتر وإيقاف المؤشر فوراً.
2. **IDLE (جاهز)**:
   - اليد ظاهرة ومفتوحة. يتحرك المؤشر بحرية لمطابقة الحرف المستهدف.
3. **PINCH_POTENTIAL (احتمال ضم)**:
   - مسافة المسافة الإقليدية بين طرف السبابة والإبهام انخفضت عن العتبة `pinch_threshold` (افتراضياً 0.055).
   - يبدأ عداد زمني للتحقق من أن الضم مقصود وليس ارتعاشاً سريعاً (`min_hold_ms` = 100ms).
4. **TRIGGERED (تم التأكيد)**:
   - إذا استمر الضم لمدة 100ms، يُرسل إشعار الضغطة **لمرة واحدة فقط** إلى محول النظام ومحرر النصوص.
5. **WAIT_RELEASE (انتظار التحرير - قفل التكرار)**:
   - تظل هذه الحالة نشطة طالما أن المستخدم يستمر في ضم أصابعه.
   - **لا يُسمح بأي إدخال جديد إطلاقاً** حتى يباعد المستخدم بين السبابة والإبهام ليتجاوز عتبة التحرير `release_threshold` (0.085).
6. **PALM_PAUSED (توقف بالكف المفتوح)**:
   - عند فتح أصابع اليد الأربعة وتوجيه الكف للأمام، تتوقف إمكانية الضغط مؤقتاً لحماية المستخدم.

## 4. إدخال النصوص على مستوى النظام (System-Level Text Injection)

### 4.1. نظام Windows
- استخدام واجهة `SendInput` الأصلية من مكتبة `user32.dll` عبر `ctypes`.
- إرسال الحروف عبر خاصية `KEYEVENTF_UNICODE`، مع تمرير كود الحرف بتشفير UTF-16 (little-endian).
- هذا يضمن دعم الحروف العربية والتشكيل والرموز اللاتينية في كافة البرامج (Notepad, Word, Chrome, Terminal) دون الاعتماد على لغة تخطيط لوحة المفاتيح النشطة في النظام ودون سحب تركيز النافذة (No focus stealing).

### 4.2. نظام Android
- ترث فئة `AirTypeIME` من `android.inputmethodservice.InputMethodService`.
- يتم إدخال النصوص مباشرة عبر `InputConnection.commitText(char, 1)`.
- دعم الحذف عبر `deleteSurroundingText(1, 0)` والانتقال لسطر جديد عبر `sendKeyEvent(KeyEvent.KEYCODE_ENTER)`.
- توفير وضع بديل باللمس (Touch Fallback) لضمان إمكانية الكتابة في حال عدم توفر إضاءة كافية للكاميرا.
